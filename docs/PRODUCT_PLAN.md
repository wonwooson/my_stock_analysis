# 시장 흐름 리서치 앱 기획안 v0.1

작성일: 2026-10-17, 한국시간.
상태: 구현 가능한 범위로 정리한 기획 초안. 앱과 데이터 수집기는 아직 미구현.
상위 기준: [제품 기준 v1.0](PRODUCT_FRAMEWORK.md).
기존 질문·답변·신호 프레임과 종목 신호 정의는 변경하지 않습니다.
이 문서의 기술 선택, 출시 범위, 운영 시간은 구현을 위한 제안입니다.

## 1. 제품 목표

정부 정책이 실제 투자와 산업 수요로 이어지는 과정을 추적합니다.
그 변화가 관심 종목에 만드는 기회와 위기를 설명합니다.
당시 판단과 이후 결과를 보존하여 복기와 통계 분석에 활용합니다.

사용자의 핵심 질문은 다음과 같습니다.
“무엇이 달라졌고, 내 종목에 왜 중요하며, 다음에는 무엇을 확인해야 하는가?”

매수·매도 주문, 실시간 매매 추천, 수익 예측은 첫 버전에 포함하지 않습니다.
손실 허용 범위는 시나리오 비교 조건이며 손실을 제한하는 보장은 아닙니다.

## 2. 사용자와 사용 방식

- 개인 사용자 1명을 위한 한국어 웹앱으로 시작합니다.
- 데스크톱에서 비교·조사하고 모바일에서 일일 요약을 확인합니다.
- 평일에는 5~10분 동안 중요한 변화와 다음 일정을 확인합니다.
- 주말에는 질문, 경쟁 구도 비교, 판단 기록에 시간을 사용합니다.
- 기본 표시 시간대는 Asia/Seoul입니다. 원문 시각과 시간대도 보존합니다.
- 투자 기간은 1년입니다. 손실 허용 범위는 사용자 입력 −10%입니다.

### 초기 자산 입력

| 사용자 입력 | 상대 금액 | 전체 비중 |
|---|---:|---:|
| 엔비디아 | 1.2 | 20.00% |
| 마이크론 | 1 | 16.67% |
| SK하이닉스 | 1 | 16.67% |
| SpaceX / SPCX | 0.5 | 8.33% |
| 리게티 컴퓨팅 | 0.5 | 8.33% |
| 마벨 | 0.5 | 8.33% |
| 알파벳 A | 0.3 | 5.00% |
| 현금 | 1 | 16.67% |

합계는 6입니다. 비중은 반올림으로 합계 차이가 생길 수 있습니다.
이 값은 사용자가 입력한 스냅샷이며 현재 시가평가액이 아닙니다.
주식 수량, 취득 원가, 평가 기준일, 현금 통화는 아직 입력되지 않았습니다.
입력 비중으로 집중도는 계산할 수 있지만 실제 투자 손익은 계산하지 않습니다.
SpaceX / SPCX는 종목 식별 미확인 상태를 유지합니다.
다른 종목도 거래소·증권 유형·고유 식별자를 확인한 뒤 데이터를 연결합니다.

## 3. 첫 버전의 범위

### 포함

1. 한국·미국의 AI 인프라 및 반도체 정책을 추적합니다.
2. 비교 자료가 있는 다른 국가의 유사 정책을 개별 등록합니다.
3. 초기 정책·사업 6~10건을 선별하고 원문을 확인합니다.
4. 초기 보유 목록과 사용자가 추가한 관찰 기업을 관리합니다.
5. 정책 단계, 기업 연결, 질문·답변·신호, 변경 이력을 제공합니다.
6. 장 마감 가격·환율과 확보 가능한 무역 시계열을 연결합니다.
7. 수출입 시계열 2~3개를 품목 분류 검증 후 시범 적용합니다.
8. 주간 검토 노트와 다음 확인 조건을 저장합니다.

정책 선정 수는 구현 목표이며 실제 조사 완료 건수가 아닙니다.
첫 버전의 국가 비교는 등록한 정책만 다룹니다.
국가 전체의 투자 규모를 포괄한다고 표현하지 않습니다.

### 이후 확장

- 중국·일본·대만·유럽의 정책·교역 자료 수집 확대.
- 피지컬 AI, 전력망, 우주, 양자 분야의 체계적인 추적.
- 한국 투자자별 수급, 미국 ETF 흐름, 기관별 13F 이력.
- 기술·공급망에서 신규 기업을 발견하는 자동 탐색.
- 장기 복기, 국가 간 사례 비교, 회귀분석.

미확장 분야와 미확인 종목도 관찰 목록에는 남깁니다.
분석 범위 밖이라는 이유로 임의의 신호를 생성하지 않습니다.

## 4. 핵심 사용자 흐름

### 평일

1. 홈에서 지난 방문 이후 중요한 변화 3~5개를 봅니다.
2. 질문과 짧은 답변, 현재 신호, 변경 이유를 확인합니다.
3. 관심 항목을 열어 정책 타임라인과 종목 연결 근거를 봅니다.
4. 다음 확인 조건을 관찰 목록에 저장합니다.

### 주말

1. 한 주의 신호 변경과 미해결 질문을 모아 봅니다.
2. 국가별 정책과 산업·교역 자료를 비교합니다.
3. “무엇이 내 생각을 바꿀 것인가?”에 답을 기록합니다.
4. 투자 가설과 다음 확인 조건을 새 버전으로 저장합니다.
5. 누적 자료가 있는 경우 과거 판단과 실제 결과를 비교합니다.

### 신규 기업 발견

정책 → 산업 → 필요한 제품 → 기업 → 공급 근거 순으로 탐색합니다.
공급 계약 확인과 공급 가능성을 분리합니다.
후보를 추가할 때 발견 이유와 반대 근거를 저장합니다.
첫 버전은 검토한 연결을 제공하고 자동 후보 탐색은 후속 단계로 둡니다.

## 5. 화면 구성과 기능 요구사항

| ID | 화면 | 질문·시각화 | 주요 조작 | 완료 조건 |
|---|---|---|---|---|
| F01 | 오늘·이번 주 | 무엇이 달라졌나? 변화 카드·일정 | 기간 변경, 상세 열기, 관찰 등록 | 변경 이유·자료 시각·다음 조건을 표시 |
| F02 | 정책·산업 지도 | 국가별 정책이 어디까지 실행됐나? 국가×산업 표 | 국가·분야 필터, 정책 비교 | 금액 성격·기간·실행 단계를 구분 |
| F03 | 정책 상세 | 실제로 집행되는가? 계획·실행 타임라인 | 사건·원문 열기, 연결 기업 확인 | 원 계획·변경 이력·마지막 확인일 보존 |

| F05 | 내 자산·관찰 목록 | 공통 노출이 얼마나 큰가? 비중·시나리오 | 금액 입력, 가정 변경, 후보 추가 | 입력 기준일과 가정을 표시하고 결과 재계산 |
| F06 | 질문·복기 노트 | 무엇을 예상했고 무엇이 달랐나? 기록 타임라인 | 질문, 메모, 확인 조건 저장 | 답변과 당시 출처를 버전별로 보존 |

모든 분석 화면은 동일한 분석 ID와 버전을 참조합니다.
현재 데이터를 보여주는 차트와 과거 판단을 함께 표시할 때는 기준 시점을 분리합니다.
색상만으로 상태를 전달하지 않습니다. 문구와 기호를 병기합니다.
그래프는 대응하는 표와 출처를 제공합니다.
빈 화면은 “문제 없음” 대신 미수집·범위 밖·갱신 실패 사유를 표시합니다.

### 공통 분석 카드

질문 → 요약 답변 → 신호 → 기회·위기 근거 → 다음 확인 조건.
보조 항목은 기준 시점, 자료 최신성, 출처, 이전 신호와의 차이입니다.
AI 답변을 열면 주장별 근거로 이동할 수 있습니다.
사용자 가설과 AI 해석은 원문 사실과 다른 표시를 사용합니다.

## 6. 신호 산출과 검토

종목 신호는 기회 우세, 기회·위기 혼재, 위기 우세, 판단 보류입니다.
정책 실행 단계와 종목 신호는 별도 값입니다.
정책 지원 증가만으로 종목의 기회 우세를 결정하지 않습니다.

### 첫 버전의 처리 순서

1. 분석 대상과 질문, 투자 기간을 지정합니다.
2. 필요한 자료 항목과 최신성 기준을 질문별로 정의합니다.
3. AI가 출처에서 사실과 근거 후보를 추출합니다.
4. 단위·기간·중복·기업 식별을 검증합니다.
5. 기회 근거, 위기 근거, 투자 가설의 무효화 조건을 비교합니다.
6. 신호 초안을 만들고 근거를 검토한 뒤 게시합니다.
7. 분석 버전과 규칙 버전, 검토 시각을 저장합니다.

첫 버전은 AI 초안을 자동으로 확정 신호에 게시하지 않습니다.
검토 전 초안은 초안으로 표시합니다. 핵심 자료 부족은 판단 보류로 처리합니다.
확정 신호도 해석이며 미래 결과를 보장하지 않습니다.
중요 근거가 서로 상충하면 기회·위기 혼재로 표시합니다.
근거 우세를 주장할 때는 그 이유와 반대 근거를 함께 기록합니다.
자의적인 확률 점수와 색상 개수의 단순 합산은 사용하지 않습니다.
구체적인 분야별 판단 규칙은 실제 사례 검토 후 버전으로 관리합니다.

### 변경 알림

새 기사 자체보다 집행 단계·계약·투자 가설·자료 유효성의 변화를 알립니다.
동일 사건을 묶어 중복 알림을 줄입니다.
알림에는 이전 신호, 새 신호, 변경 근거, 확인할 조건을 포함합니다.
첫 버전의 알림은 앱 내부에서 제공합니다.

## 7. 데이터 수집 계획

| 자료 | 우선 출처 후보 | 갱신 계획 | 검증 항목 |
|---|---|---|---|
| 정부 정책·집행 | 정부·의회·예산·조달 기관, USAspending | 하루 1회 확인, 공개 일정 반영 | 발표·확정·계약·지급 구분 |
| 기업 실적·공시 | SEC, DART, 기업 IR | 하루 1회, 실적 발표 후 확인 | 분기, 통화, 정정, 기업 식별 |
| 가격·환율 | 권한을 확보한 시장 데이터 API | 거래소 장 마감 후 | 지연, 휴장일, 조정주가, 이용권 |
| 수출입 | 관세청, UN Comtrade 등 공식 통계 | 발표 주기별 | HS 코드 버전, 금액·수량·단위 |
| 매크로 | 한국은행, 연준, FRED·ALFRED | 발표 주기별 | 대상 기간, 최초 발표와 수정치 |
| 기술·경쟁 | 공식 기술 문서, 고객 발표, 검증 자료 | 하루 1회 확인 | 시연·제품·유료 도입·매출 구분 |
| 13F·기관 자금 | SEC 원문과 사용 허가된 자료 | 후속 단계, 공시 주기별 | 기준일·공시일, 수량 보정, 공개 범위 |

출처별 접근·이용 조건은 아직 검증되지 않았습니다.
앞선 조사에서 외부 사이트 접근은 환경 프록시의 403으로 차단됐습니다.
구현 시 실제 연결을 다시 확인하고 실패한 출처는 실패 상태로 남깁니다.
유료 데이터 구매와 구독은 이 기획의 승인 범위에 포함하지 않습니다.
시연 단계에서는 명확히 표시한 가상 자료 또는 검증한 수동 입력을 사용합니다.
시연 자료를 실제 역사 분석 데이터에 합치지 않습니다.

### 수출입 분석 원칙

국가·상대국·수출입 방향·품목·기간별로 저장합니다.
명목 금액과 수량을 분리합니다. 수량이 없으면 물량 증가를 단정하지 않습니다.
품목 코드가 다른 시계열은 매핑 근거 없이 이어 붙이지 않습니다.
재수출, 중계무역, 계절성, 조업일수, 가격 효과를 검토합니다.
국가별 수출·수입 통계의 평가 방식과 운송 시차 차이를 표시합니다.
HBM이나 특정 AI 제품을 넓은 품목 통계로 정확히 식별했다고 표현하지 않습니다.

## 8. 누적 저장과 분석 구조

| 기록 | 핵심 필드 | 보존 방식 |
|---|---|---|
| 출처 문서 | URL, 발행 기관, 공개일, 수집일, 해시, 이용권 | 허용된 원문·발췌와 메타데이터 보존 |
| 사건 | 정책·기업 ID, 단계, 발생일, 확인 자료 | 정정·취소·지연도 새 사건으로 추가 |
| 수치 | 지표, 기간, 값, 단위, 통화, 출처 버전 | 수정본이 원본을 대체하지 않음 |
| 관계 | 정책·산업·기업 연결, 종류, 근거, 유효 기간 | 확인·추정 상태와 변경 이력 보존 |
| 분석 | 질문, 답변, 신호, 근거, 규칙·모델 버전 | 게시 버전을 변경하지 않고 후속 버전 추가 |
| 확인 조건 | 사건·지표, 조건, 예정일, 충족 근거 | 상태 변경 이력 보존 |
| 자산 스냅샷 | 금액·수량, 통화, 기준일, 입력 출처 | 평가 시점별 기록 |
| 결과 | 분석 ID, 평가 기간, 실적·시장 성과, 계산 버전 | 사후 결과를 당시 판단과 분리 |

발생·대상 시점, 공개 시점, 시스템 수집 시점을 각각 보존합니다.
공개 시각을 모르면 임의로 채우지 않고 불명 상태를 기록합니다.
당시 공개 정보 재구성과 앱이 당시 실제로 알던 정보를 구분합니다.
오늘 생성한 과거 시점 분석을 당시 실제 판단으로 표시하지 않습니다.
원문 보존이 제한되면 링크·허용 발췌·수치·출처 정보를 남깁니다.
삭제·비공개 전환된 원문은 링크 상태와 마지막 확인 시점을 기록합니다.

### 복기와 회귀분석

첫 버전부터 구조화된 자료와 결과 연결 ID를 저장합니다.
회귀분석 화면은 자료 축적·품질 검증 후 개발합니다.
초기 분석 단위는 정책 사건×연관 산업×발표 시점입니다.
설명 변수 후보는 집행 단계, 집행액 변화, 교역 변화, 금리, 기존 산업 추세입니다.
결과 변수 후보는 이후 1·3·6·12개월 실적 변화와 업종 대비 수익률입니다.
기간은 평가를 시작하기 전에 고정합니다.
가격 기준 시점은 실제 공개 후 거래 가능한 시점으로 정합니다.
배당·분할·상장폐지 처리는 데이터 제공 범위와 함께 명시합니다.
같은 사건에 연결된 여러 종목을 독립된 사건처럼 세지 않습니다.
시계열 순서에 따라 학습·검증 기간을 분리합니다.
표본 수, 누락, 중복, 불확실성, 분석 사양을 함께 공개합니다.
작은 표본에서는 회귀 계수 대신 사례 비교와 기술통계를 제공합니다.
관찰된 관계를 인과 효과로 단정하지 않습니다.

## 9. 기술 구성 제안

- 화면: Next.js·TypeScript, 반응형 웹, 차트·표 기반.
- 서버·데이터 처리: Python API와 정기 수집 작업.
- 저장: PostgreSQL, 허용된 문서 파일을 위한 별도 저장 공간.
- AI: 제공사 교체가 가능한 호출 계층, 출처 기반 추출·요약.
- 배포: 초기에는 단일 사용자 환경. 외부 공개 전에 인증을 적용합니다.

첫 버전에서는 별도 그래프 DB나 벡터 DB를 도입하지 않습니다.
정책·산업·기업 관계는 관계 테이블로 관리합니다.
검색 규모와 실제 병목을 확인한 뒤 확장합니다.
수집 작업은 재실행해도 중복 자료를 만들지 않도록 설계합니다.
실패 기록, 갱신 상태, 마지막 성공 시각을 관리 화면에 표시합니다.
증권 계좌 연동 없이 수동 입력으로 시작합니다.
개인 자산 기록은 공개 시연과 분리하고 사용자 자료를 로그에 노출하지 않습니다.
백업과 복원 절차는 실제 데이터 운영 전에 검증합니다.

## 10. 개발 단계와 통과 기준

| 단계 | 결과물 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1. 화면 시제품 | 핵심 6개 화면, 가상 정책 사례, 질문·신호 카드 | 평일·주말 흐름을 클릭으로 완료하고 시연 자료 표시 |
| 2. 저장 기반 | 공통 분석 기록, 버전, 출처, 자산 입력 | 재시작 후 기록 유지, 이전 판단 복원, 화면 신호 일치 |
| 3. 실제 자료 시범 운영 | 정책 6~10건, 공시·가격·무역 자료 일부 | 출처 접근·이용권 확인, 원문 대조, 갱신 실패 표시 |
| 4. 개인 사용 버전 | 주간 노트, 조건 알림, 신호 검토 흐름 | 아래 출시 기준 충족, 백업 복원 완료 |
| 5. 분석 확장 | 13F, 자금 흐름, 추가 국가·산업, 장기 복기 | 데이터 범위·시차·기업 식별 검증 |
| 6. 통계 분석 | 결과 연결, 사례 비교, 회귀분석 | 충분한 표본과 시점 정합성, 별도 기간 검증 |

일정은 외부 데이터 접근과 실제 자료 정제 결과를 본 뒤 산정합니다.
단계 1·2는 외부 API 연결 없이 진행할 수 있습니다.
실제 데이터가 차단된 상태에서는 단계 3 완료를 주장하지 않습니다.

## 11. 출시 기준과 검증

### 필수 품질 기준

- 게시된 분석 카드마다 질문·답변·신호·다음 확인 조건이 있습니다.
- 게시된 핵심 사실마다 출처가 있거나 미확인 표시가 있습니다.
- 같은 분석 버전의 홈·상세·알림 신호가 일치합니다.
- 중복 자료 재수집과 정정 공시가 과거 기록을 손상하지 않습니다.
- 자료 부족과 갱신 실패는 판단 보류 또는 자료 상태로 드러납니다.
- 과거 조회는 그 시점 이후 공개된 자료를 제외합니다.
- 정책 금액의 종류와 기간을 혼합해 합산하지 않습니다.
- 기업 식별이 미확인인 입력에 시세와 공시를 자동 연결하지 않습니다.
- 사용자 자산 입력과 신호 이력을 백업에서 복원할 수 있습니다.

### 실제로 검증할 사례

정책 재발표, 사업 취소, 부분 집행, 지연, 출처 정정 사례를 포함합니다.
같은 기사를 여러 번 수집해도 사건과 알림이 중복되지 않는지 확인합니다.
시간대를 넘는 장 마감 후 공시와 늦게 공개된 13F를 확인합니다.
무역 코드 변경과 금액·수량 단위 오류를 확인합니다.
후속 단계에서는 분할·합병·상장폐지 처리도 확인합니다.

### 사용성 목표

사용자는 홈에서 5분 안에 중요한 변화와 다음 확인 조건을 찾을 수 있습니다.
사용자는 신호 카드에서 두 번 이내 조작으로 원문 근거를 열 수 있습니다.
주말 노트에는 적어도 하나의 검증 가능한 다음 확인 조건을 남길 수 있습니다.
사용성 목표는 시제품으로 평가하며 투자 수익률을 출시 지표로 삼지 않습니다.
